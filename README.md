# Guess the Song — Android

Игра «Угадай мелодию» на Kotlin и Jetpack Compose. Приложение загружает список треков по ссылке на плейлист Spotify или Яндекс Музыки, ищет аудиопревью в iTunes и предлагает угадать трек по короткому отрывку.

## Что работает

- Загрузка плейлистов Spotify и Яндекс Музыки по ссылке.
- Раунды с четырьмя вариантами ответа, подсчёт очков и итоговый результат.
- Настройка количества раундов и длины отрывка от 1 до 30 секунд. Настройки сохраняются в DataStore.
- Сохранение загруженных плейлистов и треков в Room, отдельный экран сохранённых плейлистов.
- Кэширование ссылок на найденные аудиопревью в БД.
- Состояния загрузки и ошибки при получении плейлиста, подготовке игры и воспроизведении.

Для подготовки игры нужны хотя бы четыре разных трека, а их количество не должно быть меньше выбранного числа раундов.

## Устройство проекта

Код находится в модуле `app`:

- `presentation` — Compose-экраны, ViewModel и состояние интерфейса через StateFlow;
- `domain` — модели, интерфейсы репозиториев и логика раундов в `GameManager`;
- `data` — сетевые клиенты, преобразование ответов, репозитории, Room DAO и аудиоплеер;
- `core` — Dagger-компонент, навигация, база данных и общие настройки.

Используются Kotlin, Compose Material 3, Coroutines/Flow, Dagger с KSP, Room, DataStore, Ktor и Media3 ExoPlayer. Версии зависимостей указаны в Gradle-файлах.

## Сборка и запуск

Нужны JDK 21, Android SDK с платформой API 37 и устройство или эмулятор с Android 7.0 (API 24) или новее. В репозитории настроены Gradle Wrapper 9.8.1 и Android Gradle Plugin 9.1.1. Отдельно устанавливать Gradle не требуется.

```bash
git clone --branch develop https://github.com/MrOmichov/GuessTheSongAndroid.git
cd GuessTheSongAndroid
```

Откройте проект в Android Studio, укажите Android SDK и дождитесь синхронизации. Выберите конфигурацию `app` и запустите её на устройстве. Для игры нужен доступ в интернет.

Сборка debug APK из терминала:

```bash
./gradlew :app:assembleDebug
```

В Windows PowerShell используйте `./gradlew.bat` вместо `./gradlew`. APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Для debug-сборки не нужны ключ подписи, `keystore.properties` или учётные данные музыкальных сервисов. Импорт плейлистов реализован без входа в аккаунт пользователя.

## Тесты

```bash
./gradlew :app:testDebugUnitTest
```

В JVM-тестах проверяются парсеры ссылок, сетевые клиенты с подменёнными ответами, мапперы, репозитории, логика раундов и ViewModel списка плейлистов. Для проверки Room на подключённом устройстве или эмуляторе:

```bash
./gradlew :app:connectedDebugAndroidTest
```

Тесты, обращающиеся к настоящим музыкальным сервисам, включаются отдельно переменными окружения `RUN_ITUNES_LIVE_TESTS`, `RUN_SPOTIFY_LIVE_TESTS` и `RUN_YANDEX_LIVE_TESTS` со значением `true`. По умолчанию они пропускаются.

В `.github/workflows/android-ci.yml` настроены запуск JVM-тестов и сборка debug APK. Инструментальные тесты этим workflow не запускаются.

## Ограничения

- Это проект в разработке. Сохранённые плейлисты пока доступны для просмотра; запуск новой игры из этого экрана ещё не подключён.
- Сохраняются данные плейлистов и URL превью, а не аудиофайлы для офлайн-игры.
- Spotify-плейлисты читаются из embed-страницы, Яндекс Музыка — через её сетевые endpoints. Изменения сервисов могут сломать импорт; закрытые плейлисты не поддерживаются.
- Для трека может не найтись подходящего превью в iTunes. Сейчас такая ошибка прерывает подготовку игры, а не пропускает трек.
- Приложение использует превью из iTunes, поэтому звучащая версия записи может отличаться от версии в исходном плейлисте.
